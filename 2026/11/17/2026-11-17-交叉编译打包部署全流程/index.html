实战项目

从改一行代码到板上生效：交叉编译、打包、部署、回滚全流程

前面两篇讲结构，这篇讲落地。

这份流程是按”你明天就要自己接管”写的：每一步都有可复制的命令、一条可验收的判据、以及不按这个顺序会出什么事故。踩过的坑都标了原因，不要跳。

一、三台机器的分工，先钉死

机器 地址 账号 装的东西

板子上永远不编译。 板子只有 3G 可用空间，编一次 GStreamer 相关代码 20 分钟起步，而且交叉编译器的头文件和板端 rootfs 版本必须严格对应——在板子上编译根本编不出可用的东西。

3.1 推二进制（必须 md5 对账）

md5 对账不是形式主义。 有一次推板后发现”修复无效”，查了半小时才确认是 scp 只传了脚本没传二进制——板子上跑的还是旧程序，所有验证都白做。从此这条写进流程。

3.2 推前端

前端不需要重启 device_platform，它是每次请求现读磁盘。浏览器强刷（Ctrl+Shift+R）即可，因为 index.html 会引用带 hash 的新 assets 文件名。

3.3 推 SQL 升级脚本

注意：脚本目录是 /home/forlinx/sql/upgrade/，不是 /home/forlinx/tsl/sql/。project_root() 从 exe 剥一层，exe 在 /home/forlinx/tsl/，剥完是 /home/forlinx/tsl……那升级目录不就是 tsl/sql/upgrade？

这里有个必须解释的细节，因为它是踩过的坑：project_root() 定义在 app/util.hpp，板端路径 readlink("/proc/self/exe") 得到 /home/forlinx/tsl/device_platform，剥一层得到 /home/forlinx（不是 /home/forlinx/tsl）。所以升级脚本读的是 /home/forlinx/sql/upgrade/。

而同一次改版里，snapshot_service.hpp::exe_dir_of() 也剥了一层，得到 /home/forlinx/tsl——两处”剥一层”的起点不同（一个是 exe 全路径，一个是 exe 所在目录），结果差了一级。当时表现为”抓图记录写成功了，但网页取图 404”。现在两处已经统一，改动时一定要 grep 一遍 /proc/self/exe 确认所有地方的语义。

五、验收：五条判据，缺一条不算过

5.1 平台活着

这是最权威的判活依据。GET / 页面、pidof、watchdog 的 STATE、心跳日志都不能证明管线活着——进程在但 ISP 死了的时候，pidof 一样正常返回。

5.2 五个进程都在

STATUS 会给出每个服务的 alive / miss / restarts / fed=Ns ago。如果 restarts 一直在涨，说明有服务在反复被杀，先看 watchdogd.log 找原因。

5.3 画面真的是亮的（只能看亮度）

正常 130240，黑屏 2040。判断黑屏不能用线程数、不能用 GET 返回、不能用参数 ACK——这些全正常但画面是黑的，这个坑吃过的次数最多。参数是否真生效，用 cap 10 和 cap 240 两张图的 Yavg 差值判断（正常差一个数量级，如 3.26 vs 230.90）。

5.4 新代码真的在跑

加日志验证是最省事的自证方式。改代码时顺手 printf("[xxx] 新逻辑跑了\n")，部署后 grep 一下就知道跑的是不是新二进制。

5.5 资源不涨（长期运行的硬指标）

稳态约 40，有观众 50~100。超过 300 就是泄漏，5 分钟会撞 1024 的 fd 上限，然后 mpp 分配失败、黑屏循环。

2026-11-10 有过一次真实事故：DumbMem 这个 RAII 类只写了 release() 没写析构函数，加上 OSD 时间层每秒重建渲染对象，每秒泄漏 5 个 fd，5 分钟打满。看门狗一天自动救了 8 次，日志里只有”HTTP 探活超时”。

教训写成规矩：长驻进程里的资源封装必须有析构函数，release() 只靠人工调用不算释放；任何”周期重建/每秒渲染”的逻辑上线前必须跑一次 fd 收敛验证。

前端回滚：

数据库是最危险的。升级脚本一旦执行，tki_schema_version 就记了账，回退二进制不会回退表结构。所以：

  1. 跑新版本前先备份：cp /home/forlinx/tsl/tsl.db /home/forlinx/tsl/tsl.db.bak_$(date +%m%d)。
  2. 新写的 V0xx.sql 尽量只做 ALTER TABLE ADD COLUMN（加列对老代码是透明的），不要 DROP。
  3. 真要回退表结构，只能停服务 + 换回 db 文件 + 重启。

八、每天开工前的 30 秒检查

一条判活，一条判资源。这两条过了，剩下的问题都只是功能问题，不是”板子要炸了”的问题。

改代码的完整闭环就是：Windows 改 → VM 编 → md5 对账 → scp → restart_camera.sh → ping + 抓帧亮度 → 看日志。走完这六步，才算”改完了”。
