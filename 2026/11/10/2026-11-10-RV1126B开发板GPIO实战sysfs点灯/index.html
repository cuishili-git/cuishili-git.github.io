RV1126B 开发板 GPIO 实战：从原理图丝印到 sysfs 点灯（附三个排坑案例）

在 OK1126Bx-S（RV1126B）上做算法报警节点测试，需要一个能真正拉高拉低的 GPIO 接 LED。这件事落到 Linux 里只有几行 echo，真正费劲的是搞清楚该戳哪根针、往内核里写哪个号。本文记录从原理图选脚、编号换算、sysfs 操作到硬件排坑的完整过程。

一、先分清三套编号

同一个引脚有三套名字，这是最容易绕晕的地方：

编号体系 长什么样 用在哪
SoC 网络名 GPIO0_D1（bank+组+序号） 原理图、板载丝印
树莓派兼容号 GPIO13、GPIO22 排针丝印的绿色小字
Linux sysfs 号 25 内核 /sys/class/gpio，写命令用

最大的坑：丝印印着 GPIO13，去 export 13——错。树莓派兼容号和 sysfs 号是两套独立编号，必须从 SoC 名换算。

二、sysfs 号怎么算

内核不认识带字母的名字，RK 系列把所有 GPIO 平铺成连续整数：4 个 bank，每个 bank 32 个号，bank 内按 A/B/C/D 四组切，每组 8 个：

实测验证：

丝印名 计算 sysfs
GPIO0_C7 0×32 + 16 + 7 23
GPIO0_D1 0×32 + 24 + 1 25
GPIO3_B7 3×32 + 8 + 7 111
GPIO4_A0 4×32 + 0 + 0 128

/sys/class/gpio/ 下的 gpiochip0/32/64/96/128 就是各 bank 的起始号，算出的号落在哪个区间归哪个 chip 管，可交叉验证。

三、选脚：40 根针里只有 6 根能随便用

从原理图（OK1126Bx-S V1.1 第 6 页 P16）逐脚提取网络名后，能当「纯 GPIO」的实测结果：

排针脚号 SoC 名 sysfs 状态
33 GPIO0_D1 25 ✅ 首选，3.3V 域，实测通
36 GPIO3_B7 111 ✅ 实测通
13 GPIO4_A0 128 ✅ 实测通
15 GPIO0_C7 23 ✅ 实测通
16 GPIO4_A1 129 理论可用，未实测
7 GPIO0_C6 22 理论可用，未实测

其余 34 根不能碰：1/17/2/4 是电源（常供 3.3V/5V），6/9/14/20/25/30/34/39 是 GND，3/5 被板载 RTC 同用的 I2C4 占，19/21/23/24/26 是 SPI1，8/10 是 UART5，22/29/31/32 是 CAN，18/35 是摄像头复位/掉电（一动 MIPI 摄像头就挂），37/38/40 是蓝牙唤醒。

排针定位技巧：别从 1 数到 40，从丝印 3V3 端按行数，第 17 行就是 33/34 脚，目标脚紧挨丝印字。

四、sysfs 四步操作

Linux 把 GPIO 操作包装成读写文本文件：cat 是读电平，echo 是写电平，内核直接动寄存器。

接线：GPIO 脚 → LED 正极（长脚）→ LED 负极串 330Ω~1kΩ 电阻 → GND。

五、踩坑复盘（最有价值的部分）

坑 1：命令成功 ≠ 硬件动了

实测中 26/27 号（GPIO0_D2/D3）：export 成功、direction 写入成功，唯独 echo 1 后 cat value 读回永远是 0——文件操作全部「看起来成功」，硬件根本没动。结论：写完必须读回验证：

读回 0 就别纠结，直接换脚。这也是「实测清单」比「理论清单」值钱的原因。

坑 2：unexport 后灯不灭

unexport 之后 gpio25/ 目录消失，但引脚保持退出前的输出高电平，LED 一直亮且此时已没有 value 可写。解法：重新 export 拉低；或者养成先写 value 0 再 unexport 的顺序。

坑 3：LED 不亮的三步定位

  1. 量电压：黑表笔接 GND，红表笔戳接线针脚。读到 3.3V 说明脚没找错；读不到多半是行数数错了（两排 20 行手工数错一两行太常见）。
  2. 验 LED：把 LED 挪到 1 脚（常供 3.3V）串同阻值电阻接 GND。亮 → LED 和电阻都是好的；不亮 → 先换 LED，别再查 GPIO。
  3. 查极性：直插 LED 长脚是正极接 GPIO。反接不亮但不烧。

其他小坑：所有命令必须 sudo；export 报 Device or resource busy 说明脚被内核其他驱动占用，换脚；电阻 1kΩ 以上配老式红光 LED 会暗到像没亮，换 330Ω；「3.3V→LED→电阻→GPIO」的反向接法逻辑颠倒（写 0 亮写 1 灭）但不烧板。

六、验证结果

33 脚（sysfs 25）接 LED 实测：value 写 1 读回 1，LED 亮；写 0 读回 0，LED 灭。25/23/111/128 四个脚均通过 export → direction → value → 读回验证，可作为报警输出使用。

进阶用法：在「一切皆设备」的算法平台上，把 GPIO 报警建模为设备节点（属性 gpio_num=25），流程编排里把 YOLO 检测的命中结果接到报警节点——算法识别到目标 → hit=true → 灯亮约 0.85 秒自动熄灭，网页上点一下按钮，落到板子上就是第四节那几行 echo。

小结

步骤 动作 关键判据
选脚 原理图找纯 GPIO 网络名 避开电源/地/复用脚
换算 bank×32 + 组偏移 + 序号 GPIO0_D1 → 25
操作 export → direction → value → unexport 全程 sudo
验证 读回 value + 万用表量脚 命令成功 ≠ 硬件动
排坑 3V3 验 LED → 量针脚 → 查极性 先隔离硬件再怀疑软件
